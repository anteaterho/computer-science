# 07. 튜플

## 이 장에서 배운 것

- **튜플은 바뀌지 않는(immutable) 리스트**
  - `del a[2]`, `a.remove()` 모두 **에러** — `07_튜플_ex_01.py`에 주석으로 시도 흔적이 남아 있음
  - 값을 바꾸려면 `list()`로 바꿔서 고치고 다시 `tuple()`로 — `07_튜플_ex_02.py`의 왕복 패턴
- 튜플에서도 되는 것: `len()`, 인덱싱, 슬라이싱, `max()`, `min()`, `sum()`
- `list()` ↔ `tuple()` 상호 변환, `tuple(range(2,100,2))`
- **언패킹(unpacking)** — 이 장의 핵심
  ```python
  a, b, c, *d = nums   # 앞 세 개, 나머지는 d에 리스트로
  a, *b, c = nums      # 처음과 끝만 따로, 가운데는 b에
  ```
  → `*`는 "나머지 전부"라는 뜻
- 언패킹의 실전 활용: 최고점·최저점을 빼고 평균 내기 (`07_튜플_ex_05.py`)

  ```python

  ```
  리스트 → 튜플 → 리스트로 왕복한 뒤 아무 일도 안 일어났습니다. 튜플 변환을 연습하려던 흔적 같은데, 지금 코드에서는 지워도 결과가 같습니다. **왜 필요 없는지 설명할 수 있으면** 튜플을 제대로 이해한 것입니다.

## 더 연습하고 발전시킬 것

1. **"왜 튜플을 쓰는가"에 답하기.** 리스트가 더 편한데 왜 굳이? → *바뀌면 안 되는 값*임을 코드로 못 박기 위해서(설정값, 좌표, 요일 이름 등). 그리고 다음 장의 세트와 이어지는 이유 — **바뀌지 않는 값만 세트의 원소나 딕셔너리의 키가 될 수 있습니다.** 리스트를 딕셔너리 키로 써 보고 에러 메시지를 직접 읽어 보세요.
2. **언패킹 더 써 보기**
   - 변수 교환: `a, b = b, a` (09장 숙제에서 다시 나옵니다)
   - 함수에서 값 두 개 돌려주기: `return 최댓값, 최솟값` → `mx, mn = solution(...)`
3. **함수 여러 개 인자 받기**: `def f(*args)` — 언패킹의 `*`와 같은 기호, 반대 방향입니다.
4. 지금까지 푼 문제 중 "중간값들만 필요한" 문제를 찾아 `a, *b, c` 패턴으로 다시 써 보기.
